# Bug 修复报告：VIP 歌曲 30 秒试听无提示

## 用户原话

> 修改后端逻辑：当检索的歌曲是 VIP 歌的时候，播放 30 秒试听，并且弹窗告知用户，当前歌曲是 VIP 歌曲，只能听 30 秒试听

## 经验回查

- 是否已有相关经验：**是**
- 相关经验：T-009（VIP 不可播时 `vip_required=true` 并前端弹窗）、T-009+（play-url 缓存）
- 为什么仍然犯错：T-009 只覆盖「无 URL → 50004」，未覆盖「有 URL 但为 `freeTrialInfo` 试听片段」；可播性判断把「返回 URL」等同于完整可播，导致《下一站天后》等 VIP 曲静默只播 30 秒。

## 问题分析

- **现象**：聊天点歌《下一站天后》后自动播放，约 30 秒停止；元数据时长约 208 秒。
- **影响范围**：所有 VIP 曲目在游客/无会员 Cookie 下返回试听 URL 的荐歌、搜索、播放链路。
- **直接原因**：`GetTrackAudio` 返回带 `freeTrialInfo.end=30` 的试听 MP3，后端未识别。
- **根本原因**：`_playability_map_sync` 仅判断 `url` 是否存在，忽略 `fee` 与 `freeTrialInfo`。

## 修复方案

- **后端** `music_provider.py`：新增 `_inspect_track_audio_item`，识别 VIP 试听（`freeTrialInfo` + `fee`）；`PlayabilityInfo` 增加 `trial_preview` / `trial_duration_sec`；荐歌可播性标记 `vip_only=true, playable=true`。
- **后端** `music_service.py`：`play-url` 成功响应增加 `vip_trial`、`trial_duration_sec`、`vip_only`。
- **前端** `playerStore.ts`：播放成功后若 `vip_trial` 调用 `showVipTrialNotice` 弹窗。
- **契约** `docs/api-contracts.md`：补充 `PlayUrl` 试听字段。

## 验证方式

- **终端**：
  ```bash
  curl -s -c /tmp/c.txt -X POST http://127.0.0.1:8099/api/v1/guest/session > /dev/null
  curl -s -b /tmp/c.txt http://127.0.0.1:8099/api/v1/songs/382844/play-url
  # 应含 vip_trial: true, trial_duration_sec: 30
  ```
- **前端**：聊天输入「下一站天后」→ 自动播放 → 弹出「VIP 歌曲试听」提示，音频约 30 秒结束。
- **单测**：`pytest tests/test_track_audio_inspect.py`
