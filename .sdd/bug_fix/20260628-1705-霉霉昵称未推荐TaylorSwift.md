# Bug 修复报告：霉霉昵称未推荐 Taylor Swift

## 用户原话

> 修复搜索，用户需求想听霉霉的歌，应该推荐泰勒斯威夫特的歌曲

## 经验回查

- 是否已有相关经验：是
- 相关经验：
  - `[T-010]: 荐歌/播放/谱面一致性` — `extract_song_search_keywords` 须剥离口语前缀
  - `MOOD_STYLE_SEARCH` 情绪荐歌避免整句误搜
- 为什么仍然犯错：
  1. 情绪关键词提取优先级高于歌手名，「高兴」触发「欢快 流行」覆盖了「霉霉」
  2. `_looks_like_mood_style_target` 将一切「X的歌」视为情绪/风格描述，「霉霉的歌」被误判
  3. 缺少歌手昵称 → 正式搜索词的别名表

## 问题分析

- 现象：用户输入「我很高兴，想听霉霉的歌」，荐歌列表为「欢快 流行」类无关曲目
- 影响范围：聊天荐歌、首页心情输入等所有走 `_extract_keywords` 的入口
- 直接原因：搜索词被解析为 `欢快 流行` 而非 `Taylor Swift`
- 根本原因：关键词优先级为「情绪 > 歌名」，且未识别歌手昵称/「X的歌」中的歌手实体

## 修复方案

- 修改文件：
  - `backend/src/integrations/music_provider.py`
  - `backend/src/services/chat_service.py`
  - `backend/tests/test_music_keywords.py`
  - `backend/tests/test_chat.py`
- 修改说明：
  1. 新增 `ARTIST_ALIASES` 与 `extract_artist_search_keywords`（霉霉 → Taylor Swift 等）
  2. 修正 `_looks_like_mood_style_target`：「霉霉的歌」不再当作情绪描述
  3. 关键词优先级调整为：**歌手 > 歌名 > 情绪**
  4. 歌手请求时按 `artist_name` 匹配排序，禁用情绪歌名偏置
