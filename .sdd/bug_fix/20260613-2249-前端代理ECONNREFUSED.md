# Bug 修复报告：前端 Vite 代理 ECONNREFUSED

## 用户原话

> 前端接口路由有问题，定位问题并修复  
> Vite 报错：`http proxy error: /api/v1/guest/session` `AggregateError [ECONNREFUSED]`

## 经验回查

- 是否存在相关历史经验：**是**
- 相关条目：
  - `[T-001]`：`vite.config.ts` 必须配置 `/api` 与 `/ws` 代理
  - `[T-012]`：后端须用 `scripts/dev-backend.sh` 启动
- 结论：本次**不是路由路径配错**，而是启动顺序问题被误判为路由故障

## 为什么已有经验仍然犯错

1. 经验写了要配代理，但没写「前端单独启动时如何识别后端未就绪」
2. 终端只显示 `ECONNREFUSED`，用户容易理解为路由/接口地址错误
3. `VITE_BACKEND_PROXY_TARGET` 使用 `localhost`，在部分环境下会触发 IPv6 双栈连接尝试

## 问题分析

- **现象**：仅启动 `npm run dev` 后，页面请求 `/api/v1/*` 时 Vite 代理报 `ECONNREFUSED`
- **影响范围**：所有真实 API 请求（guest/chat/songs 等）
- **直接原因**：前端启动时后端 `8099` 端口尚未监听
- **根本原因**：开发流程要求前后端双进程，但缺少启动期健康检查与明确提示；代理目标使用 `localhost` 不够稳定

## 修复方案

- **修改文件**：
  - `frontend/vite.config.ts`：默认代理改为 `127.0.0.1:8099`；启动时探测 `/health` 并打印明确提示
  - `frontend/.env` / `frontend/.env.example`：统一 `VITE_BACKEND_PROXY_TARGET=http://127.0.0.1:8099`，补全 Mock 分项配置
  - `scripts/dev-frontend.sh`：启动前端前检查后端健康，未就绪时警告

## 验证方式

- **前端验证**：
  1. 终端 1：`./scripts/dev-backend.sh`
  2. 终端 2：`./scripts/dev-frontend.sh`（应看到 `API 代理 -> ... (后端已就绪)`）
  3. 打开 http://127.0.0.1:5199 ，Network 中 `/api/v1/guest/session` 返回 200
- **终端验证**：
  ```bash
  curl -X POST http://127.0.0.1:5199/api/v1/guest/session
  curl http://127.0.0.1:8099/health
  ```
